# Ebeep Mobile: how to build the app

This guide takes you from the current demo project to the finished final project (5 units, smartphones track). It is written for you, not for the examiner. Read it once fully before you start, then build it phase by phase.

Three rules that apply to everything below:

1. **Java only.** No Kotlin files, no Jetpack Compose. Screens are XML layouts plus `AppCompatActivity`.
2. **Simple code you can explain.** Every class should be something you can open in front of the examiner and walk through line by line. If you can't explain a line, rewrite it until you can.
3. **Mark borrowed code.** The Ministry rules say every piece of code taken from a website or generated by an AI tool has to be clearly marked in the code documentation and listed in the bibliography with a public link. That includes the code in this guide. Put a note in the Javadoc of each class you based on it (for example `Based on source [3] in the bibliography`), and list this conversation as a source. Change the code to your own style as you go. The examiner can ask what you changed and why.

## 4. How the beeper talks (the MQTT protocol)

This comes straight from the firmware in `github.com/Av1zi/Ebeep` (`src/main.cpp`, `include/Callbacks.h`, `include/TicTacToeState.h`, `include/Connect4State.h`, `include/ComposeState.h`). The phone has to speak exactly this, or the beeper will ignore it.

### Identity: the phone plays the role of "the other beeper"

The firmware is built for two devices: `Beeper_1` and `Beeper_2`. Each one knows its own ID (`BEEPER_ID`) and its partner's (`RECIVER_ID`). The phone app takes the partner's place:

| | Value for your setup |
|---|---|
| Beeper ID (the hardware) | `Beeper_1` |
| Phone ID (who the beeper thinks it talks to) | `Beeper_2` |
| MQTT username | the phone ID (`Beeper_2`). The firmware uses the device ID as the username. |
| MQTT password | the shared broker password from the firmware's `secret.h` |
| Broker | the same host and port as `secret.h` (TLS, port 8883), so the URL is `ssl://HOST:8883` |
| MQTT client ID | `Beeper_2_phone`. It must be different from any real device, or the broker disconnects one of them. |

In the app, each row in the `beepers` table stores its own beeper ID, phone ID and password. That's what makes "several beepers per user" work.

### Topics

The phone **subscribes** to everything under its own ID: `Beeper_2/#`.
The phone **publishes** under the beeper's ID.

| Topic | Direction | Payload | Notes |
|---|---|---|---|
| `Beeper_1/inbox` | phone → beeper | the message text | **retained = true**, so a sleeping beeper still gets it when it wakes |
| `Beeper_2/inbox` | beeper → phone | the message text | Retained. After you show it, publish an empty retained message to clear it (the firmware does the same). Ignore empty payloads. |
| `Beeper_1/games` | phone → beeper | `TTT_START`, `TTT_START_ACK`, `TTT_LEFT`, `C4_START`, `C4_START_ACK`, `C4_LEFT` | invitations and leaving |
| `Beeper_2/games` | beeper → phone | same words | |
| `Beeper_1/games/TTT` | phone → beeper | a move `"row,col"` (for example `"1,2"`), `TTT_REMATCH`, `TTT_REMATCH_ACK` | |
| `Beeper_2/games/TTT` | beeper → phone | same | |
| `Beeper_1/games/C4` | phone → beeper | a column digit `"0"`–`"6"`, `C4_REMATCH`, `C4_REMATCH_ACK` | |
| `Beeper_2/games/C4` | beeper → phone | same | |

### Message rules

- Allowed characters: `" ABCDEFGHIJKLMNOPQRSTUVWXYZ.!?<3"` (space, capital A–Z, `.`, `!`, `?`, `<`, `3`).
- Maximum 30 characters (`MAX_MSG_LEN` in `config.h`).

### Starting a game (handshake)

Example for tic-tac-toe. Connect 4 is the same with `C4_` instead of `TTT_`.

**The phone invites:**
1. Phone sends `TTT_START` to `Beeper_1/games`.
2. On the beeper, the user opens Tic-Tac-Toe. The beeper replies `TTT_START_ACK`.
3. Phone receives `TTT_START_ACK`: the phone is the **initiator**, plays **X** and **moves first**.

**The beeper invites:**
1. Phone receives `TTT_START` on `Beeper_2/games`, and the invitation dialog opens.
2. User taps Accept: the phone sends `TTT_START_ACK`, plays **O** and waits.
3. User taps Decline: the phone sends `TTT_LEFT`.

**Both invite at the same moment:** the phone is waiting for an answer and receives `TTT_START`. The firmware breaks the tie by comparing IDs: the smaller ID becomes the initiator. Do the same: `phoneId.compareTo(beeperId) < 0` means the phone is the initiator. Otherwise it joins: send `TTT_START_ACK` and play second.

**During the game:** send your move to `Beeper_1/games/TTT`. Moves from the beeper arrive on `Beeper_2/games/TTT`.

**Leaving:** send `TTT_LEFT` to `Beeper_1/games` (the general games topic, not the game's own topic). If you receive `TTT_LEFT`, the beeper left.

**Rematch:** send `TTT_REMATCH` on the game topic. If the answer is `TTT_REMATCH_ACK`, you start. If you receive `TTT_REMATCH` and didn't ask, show a dialog. On accept, send `TTT_REMATCH_ACK` and play second. If both asked at once, use the same ID tie-break.

### Important: the beeper sleeps

The beeper deep-sleeps and wakes every 30 seconds (every 2 minutes at night or on low battery). Inbox messages are retained, so they always arrive. Game messages are not retained, so the beeper only sees an invitation while it's awake. When you demo the games, press a button on the beeper first so it stays awake for 10 minutes. Mention this in the project book (see section 19).

### Test without the hardware first

Install **MQTT Explorer** on your computer and connect it to the same broker with the `Beeper_1` username. You can now act as the beeper: publish to `Beeper_2/inbox`, send `TTT_START`, and watch what the phone sends. Do this for every phase before you try the real beeper.

## 6. Code style rules (so it doesn't look generated)

Examiners have seen a lot of generated code. These are the things that give it away, and what to do instead.

**Comments**
- Write short comments that say *why*, in plain English, like your demo already does (`// No duplicate emails`).
- Don't number steps (`// Step 1:`), don't use emoji, and don't put a Javadoc block on every getter.
- Every class gets one short Javadoc saying what it's for (the book requires Javadoc). Main methods get one too.

**Naming**
- Views: `btnSend`, `editMessage`, `txtStatus`, `listBeepers`. Pick one style and keep it everywhere.
- Constants: `MAX_MESSAGE_LENGTH`, not magic numbers in the code.
- No `Manager`/`Helper`/`Util` classes unless they really do one clear job. `DatabaseHelper` is fine because that's what Android calls it.

**Size**
- Methods under about 30 lines. If `onCreate` grows, split it into `setUpViews()`, `setUpListeners()`, `loadData()`.
- One activity per screen, and an activity only talks to views and calls other classes.

**What not to add**
- Code "for later", unused parameters, interfaces with one implementation "just in case", or try/catch blocks that silently swallow errors.
- Generic `Utils` classes with ten unrelated static methods.
- Clever one-liners. Two clear lines are better.

**UI**
- Every visible string goes in `res/values/strings.xml`, in Hebrew.
- Use `start`/`end`, never `left`/`right`, so RTL works. Keep `android:supportsRtl="true"`.
- One accent color plus neutral greys. No gradients and no emoji in the UI. Use the same margins everywhere (16dp around screens, 8dp between related items).
- Use Material icons from Android Studio (New → Vector Asset), not random PNGs.

### 8.4 Secrets

Private values go in `secrets.properties` in the project root. It works like a `.env` file. Android can't read a `.env` file at runtime, so Gradle reads this file at build time and turns each value into a constant in the generated `BuildConfig` class. The file is in `.gitignore`:

```properties
BROKER_HOST=your-broker.hivemq.cloud
BROKER_PORT=8883
CLAUDE_API_KEY=your key from console.anthropic.com
```

`app/build.gradle.kts` loads the file and declares one `buildConfigField` per value, with `buildFeatures { buildConfig = true }`. The code then uses `BuildConfig.BROKER_HOST`, `BuildConfig.CLAUDE_API_KEY`, and so on.

`secrets.properties.example` is committed with fake values, so anyone cloning the repo knows what to fill in. Write in the book that the values still end up inside the APK, where a determined person could dig them out, and that a real product would keep the API key on its own server. For a school project, keeping them out of GitHub is enough.

### 9.2 DatabaseHelper

Same style as your demo, just more tables. The important parts:

```java
package com.ebeep.mobile.data;

/**
 * The app's SQLite database: users, the beepers each user connected,
 * and the results of the games against each beeper.
 */
public class DatabaseHelper extends SQLiteOpenHelper {

    private static final String DATABASE_NAME = "ebeep.db";
    private static final int DATABASE_VERSION = 1;

    public DatabaseHelper(Context context) {
        super(context, DATABASE_NAME, null, DATABASE_VERSION);
    }

    // Foreign keys are off by default in SQLite. Without this, ON DELETE CASCADE does nothing.
    @Override
    public void onConfigure(SQLiteDatabase database) {
        database.setForeignKeyConstraintsEnabled(true);
    }

    @Override
    public void onCreate(SQLiteDatabase database) {
        database.execSQL("CREATE TABLE users (" +
                "id INTEGER PRIMARY KEY AUTOINCREMENT, " +
                "username TEXT UNIQUE NOT NULL, " +
                "password_hash TEXT NOT NULL)");

        database.execSQL("CREATE TABLE beepers (" +
                "id INTEGER PRIMARY KEY AUTOINCREMENT, " +
                "user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE, " +
                "nickname TEXT NOT NULL, " +
                "beeper_id TEXT NOT NULL, " +
                "phone_id TEXT NOT NULL, " +
                "mqtt_password TEXT NOT NULL, " +
                "last_message TEXT, " +
                "last_message_mine INTEGER, " +
                "last_message_time INTEGER)");

        database.execSQL("CREATE TABLE game_records (" +
                "id INTEGER PRIMARY KEY AUTOINCREMENT, " +
                "beeper_id INTEGER NOT NULL REFERENCES beepers(id) ON DELETE CASCADE, " +
                "game TEXT NOT NULL, " +
                "result TEXT NOT NULL, " +
                "played_at INTEGER NOT NULL)");
    }

    @Override
    public void onUpgrade(SQLiteDatabase database, int oldVersion, int newVersion) {
        database.execSQL("DROP TABLE IF EXISTS game_records");
        database.execSQL("DROP TABLE IF EXISTS beepers");
        database.execSQL("DROP TABLE IF EXISTS users");
        onCreate(database);
    }
```

```java
    /**
     * Counts wins, losses and draws for each game against one beeper.
     * The key is the game ("TTT"/"C4"), the value is {wins, losses, draws}.
     */
    public HashMap<String, int[]> getGameSummary(long beeperRowId) {
        HashMap<String, int[]> summary = new HashMap<>();
        Cursor cursor = getReadableDatabase().rawQuery(
                "SELECT game, result, COUNT(*) FROM game_records " +
                "WHERE beeper_id = ? GROUP BY game, result",
                new String[]{String.valueOf(beeperRowId)});
        try {
            while (cursor.moveToNext()) {
                String game = cursor.getString(0);
                String result = cursor.getString(1);
                int count = cursor.getInt(2);

                if (!summary.containsKey(game)) {
                    summary.put(game, new int[3]);
                }
                int[] counts = summary.get(game);
                if (result.equals("WIN")) counts[0] = count;
                else if (result.equals("LOSS")) counts[1] = count;
                else counts[2] = count;
            }
            return summary;
        } finally {
            cursor.close();
        }
    }
```

### 9.4 PasswordHasher

```java
/** Turns a password into a SHA-256 hash, so the real password is never stored. */
public class PasswordHasher {

    public static String hash(String password) {
        try {
            MessageDigest digest = MessageDigest.getInstance("SHA-256");
            byte[] bytes = digest.digest(password.getBytes(StandardCharsets.UTF_8));

            // Every byte becomes two hex characters
            StringBuilder hex = new StringBuilder();
            for (byte b : bytes) {
                hex.append(String.format("%02x", b));
            }
            return hex.toString();
        } catch (NoSuchAlgorithmException e) {
            // Every Android device has SHA-256, so this can't really happen
            throw new RuntimeException(e);
        }
    }
}
```

## 11. Phase 3: the MQTT connection

### 11.1 Protocol

All the protocol words live in one class, so there are no strings scattered through the screens:

```java
/** Topic names and message words the beeper firmware understands. */
public class Protocol {

    public static final String INBOX = "/inbox";
    public static final String GAMES = "/games";
    public static final String GAME_TOPIC_TTT = "/games/TTT";
    public static final String GAME_TOPIC_C4 = "/games/C4";

    public static final String TTT = "TTT";
    public static final String C4 = "C4";

    // The words are built as GAME + "_START", for example "TTT_START"
    public static final String START = "_START";
    public static final String START_ACK = "_START_ACK";
    public static final String LEFT = "_LEFT";
    public static final String REMATCH = "_REMATCH";
    public static final String REMATCH_ACK = "_REMATCH_ACK";

    // The beeper's keyboard only has these characters
    public static final String ALLOWED_CHARS = " ABCDEFGHIJKLMNOPQRSTUVWXYZ.!?<3";
    public static final int MAX_MESSAGE_LENGTH = 30;

    /** Keeps only characters the beeper can show, in capitals, cut to 30. */
    public static String cleanForBeeper(String text) {
        StringBuilder clean = new StringBuilder();
        String upper = text.toUpperCase();
        for (int i = 0; i < upper.length() && clean.length() < MAX_MESSAGE_LENGTH; i++) {
            char c = upper.charAt(i);
            if (ALLOWED_CHARS.indexOf(c) >= 0) {
                clean.append(c);
            }
        }
        return clean.toString().trim();
    }
}
```

### 11.2 BeeperConnection

This is the heart of the networking. There is **one instance for the whole app** (a singleton), because there's one connection to the broker. It does three jobs:

1. Connects to the broker and subscribes to `phoneId/#`.
2. Publishes to `beeperId/...` on a background thread. Android doesn't allow network calls on the main thread.
3. Passes every arriving message to the main thread with a `Handler`. Paho calls `messageArrived` on its own thread, and you can't touch views from there.

```java
package com.ebeep.mobile.net;

/**
 * The single MQTT connection between the phone and the open beeper.
 * Screens and the service listen to it; anyone can send through it.
 */
public class BeeperConnection implements MqttCallbackExtended {

    /** Gets messages and connection changes, always on the main thread. */
    public interface Listener {
        void onBeeperMessage(String subTopic, String text);
        void onConnectionChanged(boolean connected);
    }

    private static BeeperConnection instance;

    private MqttClient client;
    private Beeper beeper;

    // The service listens all the time; a screen listens only while it's open
    private Listener serviceListener;
    private Listener screenListener;

    // Paho calls us on its own thread; this Handler moves the work to the main thread
    private final Handler mainHandler = new Handler(Looper.getMainLooper());

    public static BeeperConnection get() {
        if (instance == null) {
            instance = new BeeperConnection();
        }
        return instance;
    }

    public void connect(Beeper beeperToOpen) {
        // Already connected to this beeper: nothing to do
        if (isConnected() && beeper != null && beeper.getId() == beeperToOpen.getId()) {
            return;
        }
        disconnect();
        beeper = beeperToOpen;

        new Thread(() -> {
            try {
                client = new MqttClient(BROKER_URL,
                        beeper.getPhoneId() + "_phone", new MemoryPersistence());

                MqttConnectOptions options = new MqttConnectOptions();
                options.setUserName(beeper.getPhoneId());
                options.setPassword(beeper.getMqttPassword().toCharArray());
                options.setAutomaticReconnect(true);
                options.setCleanSession(true);

                client.setCallback(this);
                client.connect(options);
                // The subscription is made in connectComplete, so it also happens after reconnects
            } catch (MqttException e) {
                notifyConnectionChanged(false);
            }
        }).start();
    }

    public void disconnect() {
        if (client == null) return;
        MqttClient oldClient = client;
        client = null;
        new Thread(() -> {
            try {
                oldClient.disconnect();
                oldClient.close();
            } catch (MqttException e) {
                // It's being thrown away anyway
            }
        }).start();
    }

    public boolean isConnected() {
        return client != null && client.isConnected();
    }

    /** Sends to the beeper, for example sendToBeeper(Protocol.INBOX, "HI", true). */
    public void sendToBeeper(String subTopic, String text, boolean retained) {
        if (!isConnected()) return;
        String topic = beeper.getBeeperId() + subTopic;
        new Thread(() -> {
            try {
                client.publish(topic, text.getBytes(StandardCharsets.UTF_8), 1, retained);
            } catch (MqttException e) {
                notifyConnectionChanged(false);
            }
        }).start();
    }

    /** Clears the retained message in our own inbox, like the firmware does after reading. */
    public void clearMyInbox() {
        if (!isConnected()) return;
        String topic = beeper.getPhoneId() + Protocol.INBOX;
        new Thread(() -> {
            try {
                client.publish(topic, new byte[0], 1, true);
            } catch (MqttException e) {
                notifyConnectionChanged(false);
            }
        }).start();
    }

    // ---- MqttCallbackExtended (these run on Paho's thread) ----

    @Override
    public void connectComplete(boolean reconnect, String serverURI) {
        try {
            client.subscribe(beeper.getPhoneId() + "/#", 1);
        } catch (MqttException e) {
            notifyConnectionChanged(false);
            return;
        }
        notifyConnectionChanged(true);
    }

    @Override
    public void connectionLost(Throwable cause) {
        notifyConnectionChanged(false);
    }

    @Override
    public void messageArrived(String topic, MqttMessage message) {
        String text = new String(message.getPayload(), StandardCharsets.UTF_8);
        // "Beeper_2/games/TTT" -> "/games/TTT"
        String subTopic = topic.substring(beeper.getPhoneId().length());

        mainHandler.post(() -> {
            if (serviceListener != null) serviceListener.onBeeperMessage(subTopic, text);
            if (screenListener != null) screenListener.onBeeperMessage(subTopic, text);
        });
    }

    @Override
    public void deliveryComplete(IMqttDeliveryToken token) {
        // Not needed
    }

    private void notifyConnectionChanged(boolean connected) {
        mainHandler.post(() -> {
            if (serviceListener != null) serviceListener.onConnectionChanged(connected);
            if (screenListener != null) screenListener.onConnectionChanged(connected);
        });
    }

    // getBeeper(), setServiceListener(...), setScreenListener(...)
}
```

Things to be able to explain:
- Why a singleton: every screen needs the same connection.
- Why `new Thread`: network on the main thread throws `NetworkOnMainThreadException`, and it would freeze the UI.
- Why the `Handler`: views can only be changed from the main (UI) thread.
- QoS 1 means "at least once". Retained means the broker keeps the last message for whoever subscribes later.
- `setAutomaticReconnect(true)` retries after the network comes back. That's why subscribing happens in `connectComplete`.

## 12. Phase 4: the background service, notifications and system events

### 12.1 Why a service

Without a service, Android may kill the connection a few minutes after the user leaves the app, and invitations and messages would be missed. A **foreground service** shows a permanent notification ("מחובר לביפר X") and keeps the process alive. This is a meaningful Service, connected to what the app does, which is what list item 6.3 asks for. "A service that plays music" would not count.

### 12.2 BeeperService

```java
/**
 * Keeps the connection to the open beeper alive while the app is in the background,
 * saves incoming messages and shows notifications when no screen is open.
 */
public class BeeperService extends Service implements BeeperConnection.Listener {

    public static final String EXTRA_BEEPER_ROW_ID = "beeper_row_id";
    private static final int FOREGROUND_ID = 1;

    @Override
    public int onStartCommand(Intent intent, int flags, int startId) {
        long beeperRowId = intent.getLongExtra(EXTRA_BEEPER_ROW_ID, -1);

        DatabaseHelper database = new DatabaseHelper(this);
        Beeper beeper = database.getBeeper(beeperRowId);
        database.close();

        if (beeper == null) {
            stopSelf();
            return START_NOT_STICKY;
        }

        ServiceCompat.startForeground(this, FOREGROUND_ID,
                Notifications.connectedNotification(this, beeper),
                ServiceInfo.FOREGROUND_SERVICE_TYPE_REMOTE_MESSAGING);

        BeeperConnection.get().setServiceListener(this);
        BeeperConnection.get().connect(beeper);
        return START_NOT_STICKY;
    }

    @Override
    public void onBeeperMessage(String subTopic, String text) {
        Beeper beeper = BeeperConnection.get().getBeeper();

        if (subTopic.equals(Protocol.INBOX) && !text.isEmpty()) {
            DatabaseHelper database = new DatabaseHelper(this);
            database.saveLastMessage(beeper.getId(), text, false);
            database.close();

            if (!App.isAnyScreenOpen()) {
                Notifications.showMessage(this, beeper, text);
            }
        } else if (subTopic.equals(Protocol.GAMES) && text.endsWith(Protocol.START)) {
            // The invitation dialog only works while a screen is open
            if (!App.isAnyScreenOpen()) {
                Notifications.showInvitation(this, beeper, text);
            }
        }
    }

    @Override
    public void onConnectionChanged(boolean connected) {
        // The banner on the screens shows this; nothing to do here
    }

    @Override
    public void onDestroy() {
        BeeperConnection.get().setServiceListener(null);
        BeeperConnection.get().disconnect();
        super.onDestroy();
    }

    @Override
    public IBinder onBind(Intent intent) {
        return null;  // Started service, not bound
    }
}
```

`App.isAnyScreenOpen()` can be a static counter that `BaseActivity` increments in `onResume` and decrements in `onPause`. That's simpler than asking Android which activity is on top.

## 14. Phase 6: game logic and unit tests

The game rules are plain Java with **no Android imports**. That's the logic/UI separation the rubric asks for, and it lets you test them with JUnit.

### 14.1 BoardGame (abstract)

```java
package com.ebeep.mobile.game;

/** What every two-player board game against the beeper has in common. */
public abstract class BoardGame {

    public static final int PLAYING = 0;
    public static final int WIN = 1;
    public static final int LOSS = 2;
    public static final int DRAW = 3;

    protected static final char EMPTY = ' ';

    protected final char[][] board;
    protected final char mySymbol;
    protected final char opponentSymbol;
    protected boolean myTurn;
    protected int result = PLAYING;

    protected BoardGame(int rows, int cols, char mySymbol, char opponentSymbol, boolean iStart) {
        board = new char[rows][cols];
        for (int row = 0; row < rows; row++) {
            for (int col = 0; col < cols; col++) {
                board[row][col] = EMPTY;
            }
        }
        this.mySymbol = mySymbol;
        this.opponentSymbol = opponentSymbol;
        this.myTurn = iStart;
    }

    /** True if this symbol has a winning line. Each game checks differently. */
    protected abstract boolean hasWon(char symbol);

    /** Called after every move: updates the result and passes the turn. */
    protected void afterMove(char symbol) {
        if (hasWon(symbol)) {
            result = (symbol == mySymbol) ? WIN : LOSS;
        } else if (isBoardFull()) {
            result = DRAW;
        }
        myTurn = (symbol == opponentSymbol);
    }

    protected boolean isBoardFull() {
        for (char[] row : board) {
            for (char cell : row) {
                if (cell == EMPTY) return false;
            }
        }
        return true;
    }

    public char getCell(int row, int col) { return board[row][col]; }
    public boolean isMyTurn() { return myTurn && result == PLAYING; }
    public int getResult() { return result; }
    public char getMySymbol() { return mySymbol; }
}
```

### 14.2 TicTacToeGame

```java
/** Tic-tac-toe on a 3x3 board. The initiator is X and moves first, like the firmware. */
public class TicTacToeGame extends BoardGame {

    public TicTacToeGame(boolean iStart) {
        super(3, 3, iStart ? 'X' : 'O', iStart ? 'O' : 'X', iStart);
    }

    /** My move. Returns false if it isn't allowed. */
    public boolean playMine(int row, int col) {
        if (!isMyTurn() || board[row][col] != EMPTY) return false;
        board[row][col] = mySymbol;
        afterMove(mySymbol);
        return true;
    }

    /** The beeper's move, from a message like "1,2". */
    public boolean playOpponent(String move) {
        if (myTurn || result != PLAYING) return false;
        if (move.length() != 3 || move.charAt(1) != ',') return false;

        int row = move.charAt(0) - '0';
        int col = move.charAt(2) - '0';
        if (row < 0 || row > 2 || col < 0 || col > 2 || board[row][col] != EMPTY) return false;

        board[row][col] = opponentSymbol;
        afterMove(opponentSymbol);
        return true;
    }

    /** The message to send for my move. */
    public static String moveToMessage(int row, int col) {
        return row + "," + col;
    }

    @Override
    protected boolean hasWon(char s) {
        for (int i = 0; i < 3; i++) {
            if (board[i][0] == s && board[i][1] == s && board[i][2] == s) return true;  // row
            if (board[0][i] == s && board[1][i] == s && board[2][i] == s) return true;  // column
        }
        return (board[0][0] == s && board[1][1] == s && board[2][2] == s)
                || (board[0][2] == s && board[1][1] == s && board[2][0] == s);
    }
}
```

### 14.3 ConnectFourGame

```java
    /** The lowest empty row in this column, or -1 if the column is full. */
    public int dropRow(int col) {
        for (int row = ROWS - 1; row >= 0; row--) {
            if (board[row][col] == EMPTY) return row;
        }
        return -1;
    }

    /** Counts the same symbol in a line, starting next to (row, col) and walking (dRow, dCol). */
    private int countInDirection(int row, int col, int dRow, int dCol, char s) {
        int count = 0;
        int r = row + dRow;
        int c = col + dCol;
        while (r >= 0 && r < ROWS && c >= 0 && c < COLS && board[r][c] == s) {
            count++;
            r += dRow;
            c += dCol;
        }
        return count;
    }
```

Win check: for every cell holding the symbol, test the four directions (horizontal, vertical, two diagonals). In each direction, `1 + countInDirection(forward) + countInDirection(backward) >= 4` is a win. Explaining this in the book (with a drawing) is a good "complex logic" section.

```java
            }

        }
```

## 16. Phase 8: the AI reply suggestion

This covers the required AI topic (6.12, GenAI through an API).

**Feature:** in the chat, a "הצע תשובה" button sends the last message from the beeper to Claude. Claude answers with a short reply the beeper can show, and the reply goes into the text field. The user can edit it before sending.

```java
package com.ebeep.mobile.ai;

/**
 * Asks Claude for a short reply to the last message from the beeper.
 * The answer is cleaned so the beeper can show it (capitals, max 30 characters).
 */
public class ReplySuggester {

    public interface Callback {
        void onSuggestion(String reply);
        void onFailed();
    }

    private static final String INSTRUCTIONS =
            "You suggest a short, friendly reply to a text message. "
            + "Answer with the reply only, in English, at most 30 characters, "
            + "using only capital letters A-Z, spaces and . ! ? "
            + "You may use <3 for a heart.";

    public static void suggest(Activity activity, String lastMessage, Callback callback) {
        // Network calls are not allowed on the main thread
        new Thread(() -> {
            String reply = askClaude(lastMessage);
            activity.runOnUiThread(() -> {
                if (reply == null || reply.isEmpty()) {
                    callback.onFailed();
                } else {
                    callback.onSuggestion(reply);
                }
            });
        }).start();
    }

    private static String askClaude(String lastMessage) {
        try {
            AnthropicClient client = AnthropicOkHttpClient.builder()
                    .apiKey(BuildConfig.CLAUDE_API_KEY)
                    .build();

            MessageCreateParams params = MessageCreateParams.builder()
                    .model("claude-opus-5-5")
                    .maxTokens(2000L)
                    // A short reply doesn't need deep thinking; low effort keeps it fast
                    .outputConfig(OutputConfig.builder().effort(OutputConfig.Effort.LOW).build())
                    .system(INSTRUCTIONS)
                    .addUserMessage("The message I got: " + lastMessage)
                    .build();

            Message response = client.messages().create(params);

            StringBuilder text = new StringBuilder();
            for (ContentBlock block : response.content()) {
                if (block.isText()) {
                    text.append(block.asText().text());
                }
            }
            return Protocol.cleanForBeeper(text.toString());
        } catch (Exception e) {
            // No internet, bad key, server error: the button just says it failed
            return null;
        }
    }
}
```

Imports come from `com.anthropic.client`, `com.anthropic.client.okhttp` and `com.anthropic.models.messages`. In `ChatActivity`, disable the button and show a small `ProgressBar` while waiting. On success, put the text in the field. On failure, show a Toast ("לא הצלחתי להציע תשובה").

Notes for the book and the exam:
- **Why `cleanForBeeper` again:** the model is asked to follow the rules, but the app must never trust outside input. The same filter as the keyboard is applied.
- **If Claude refuses or returns nothing:** the response has no text block, so `onFailed` runs. The SDK also offers an automatic fallback to another model on refusal. It was left out to keep the code simple, and it isn't needed for one-line chat replies.
- **The key in the app:** acceptable for a school project, but anyone can extract it from the APK. A real product would call its own small server. Say that before the examiner does.
- **Cost:** one call is a fraction of a cent. Still, set a monthly spend limit in the Anthropic console.
- Describe the prompt (`INSTRUCTIONS`) in the book, and why each rule is in it.

## 19. Known limitations to mention honestly

Writing these yourself scores better than having the examiner find them.

- **The beeper sleeps.** Invitations reach it only when it's awake. Messages are retained, so they always arrive. Possible fix: send invitations as retained messages too, which needs a firmware change.
- **No "online" signal from the beeper.** The status shows the phone's connection and when the beeper was last heard from.
- **One open beeper at a time.** The service connects only to the beeper you opened last. Invitations from your other beepers arrive after you open them.
- **The API key and broker password are inside the app.** A real product would use a server.
- **The firmware pairs exactly two IDs.** The phone takes the partner's ID, so the phone and a second physical beeper can't both be connected as the partner at the same time.
